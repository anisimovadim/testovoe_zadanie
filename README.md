# Объекты и задачи

Мини-CRM строительной компании. React, TypeScript, Vite, React Bootstrap и Supabase. Интерфейс на русском языке.

## Запуск локально

Понадобятся Node.js 22.12+ и запущенный Docker Desktop с Linux-контейнерами. Команды выполняются из каталога проекта.

1. Установите зависимости: `npm ci`.
2. Запустите Supabase: `npx supabase@2.90.0 start -x storage-api,imgproxy,realtime,edge-runtime,logflare,vector,studio,postgres-meta,supavisor,mailpit`. Первый запуск скачивает образы и применяет SQL-миграцию. При повторном запуске используются сохранённые данные.
3. Скопируйте `.env.example` в `.env.local`. Укажите URL API и **публичный** Publishable key (или anon key) из вывода `npx supabase@2.90.0 status`.
4. Скопируйте `.env.seed.example` в `.env.seed`. Укажите тот же URL, публичный ключ, серверный Secret key (или service_role) и отдельный демонстрационный пароль длиной от 12 символов.
5. Выполните `npm run seed:demo`. Скрипт создаёт три аккаунта, три стройки и пять задач. Для повторного запуска используйте тот же пароль. Скрипт пропускает уже существующие демонстрационные задачи.
6. Запустите `npm run dev` и откройте адрес из терминала, обычно http://localhost:5173.

| Роль              | Email                  |
| ----------------- | ---------------------- |
| Постановщик       | manager@kontur.example |
| Исполнитель Илья  | worker1@kontur.example |
| Исполнитель Мария | worker2@kontur.example |

Демонстрационные аккаунты используют пароль из `DEMO_PASSWORD`. Скрипт подготовки и файл `.env.seed` используются только на машине администратора. В сборку браузера передаются исключительно две переменные с префиксом `VITE_`.

## Проверка

`npm run build` проверяет TypeScript и собирает приложение в `dist/`. После заполнения демонстрационной базы выполните `node --env-file=.env.seed scripts/check-access.mjs`. Проверка использует публичный ключ, входит под тремя пользователями, создаёт временный объект и удаляет его в конце. Она проверяет закрытую регистрацию, чтение и изменение чужих данных, одновременный переход, обязательность комментария и защиту истории.

Для ручной проверки откройте объект «Береговой» под Ильёй и возьмите в работу задачу «Проверить армирование плиты». Отправьте её на проверку, войдите под постановщиком и верните на доработку с комментарием. Илья увидит причину в истории. Мария увидит на этой стройке только свою задачу.

## Публикация

1. В выделенном проекте Supabase включите вход по email и паролю, отключите **Allow new users to sign up** в настройках Auth. Для существующей базы сначала проверьте список миграций и совпадения имён таблиц.
2. В авторизованном Supabase CLI выполните `supabase link --project-ref <идентификатор>`, проверьте план `supabase db push --dry-run`, затем выполните `supabase db push`.
3. В локальном `.env.seed` укажите облачные реквизиты и пароль для демонстрации. Выполните `npm run seed:demo` и проверку доступа.
4. На площадке статического хостинга задайте `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY` облачного проекта до сборки. Команда сборки — `npm run build`, публикуемый каталог — `dist`. Навигация по карточкам использует hash-ссылки, которые работают при прямом открытии и обновлении страницы.

Миграция лежит в `supabase/migrations/`. В `docs/overview.md` описана работа CRM для руководителя. В `docs/decisions.md` перечислены допущения и границы реализации.
