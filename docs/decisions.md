# Решения и допущения

- Каждый пользователь имеет одну роль. Любой постановщик может работать с любым объектом. Назначить задачу можно только исполнителю. Один исполнитель может работать на нескольких стройках.
- Описание задачи можно оставить пустым. Название задачи, объект, исполнитель, название и адрес стройки обязательны. Автор и дата определяются базой, а имена пользователей задаёт администратор.
- Создание задачи отражается первой записью в истории. Дальше записываются все смены статуса. Текстовые правки и смена исполнителя не меняют статус и не добавляют событий в историю статусов.
- При переназначении прежний исполнитель теряет доступ. Новый получает карточку и всю её историю. Если это было последнее поручение на стройке, прежнему исполнителю становится недоступна и стройка.
- Принятая задача завершена. Постановщик может поправить реквизиты карточки, но открыть заново завершённую работу нельзя.
- Переход проверяется по текущему состоянию под блокировкой строки. Новое состояние и запись истории сохраняются вместе. При конкурирующих запросах второй запрос проверяется уже после первого.
- Удаление физическое, с подтверждением и каскадом. История защищена от отдельных операций редактирования и удаления через API. Удаление самой задачи или стройки постановщиком удаляет и связанную историю.
- Эта версия рассчитана на одну компанию. Обмен между сессиями происходит при открытии рабочего пространства или по кнопке обновления. После собственных изменений список обновляется автоматически.
- Для локальной проверки используется настоящий Supabase в Docker. Публичная ссылка, перенос миграции в облако и отправка исходников в удалённый GitHub-репозиторий требуют настроенного доступа к соответствующим проектам.
